# 项目配置与自动依赖

状态：2026-11-01 已实现。本文记录当前 CLI 契约，替代旧的 JSON 配置、Adapter command/inputs 和手写 manifest 接入要求。不提供旧 CLI 格式兼容入口。

## 最小配置与路径

项目根的 `engdoc.config.js`：

```js
export default {};
```

运行 `engdoc`，读取 `README.md`，自动扫描 `docs/ir/`，生成 `output/index.html`。纯正文项目没有 docs/ir 目录也能构建。配置文件本身必须存在。

`engdoc --config path/to/custom.js` 使用指定配置，不与默认文件合并。未指定时只找当前目录的 engdoc.config.js，不向父目录搜索。显式配置支持 .js/.mjs/.cjs，配置内相对路径以配置所在目录为项目根；CLI `--output` 相对当前执行目录。

| 配置项 | 缺省值与含义 |
| --- | --- |
| title | 项目目录名称 |
| projectId | 项目目录名称；需要长期稳定身份时显式指定 |
| documents | 优先 README.md，不存在时发现 docs/；接受文件、目录或有序路径数组 |
| data | docs/ir；自动递归发现该目录的标准 JSON 工程数据 |
| views / tables / waveforms / references | 空数组；直接在配置内填写相应定义 |
| output.html | output/index.html；false 关闭 |
| output.pdf | false；指定 .pdf 路径后生成 |
| chromiumExecutable | 可选的已有 Chromium 路径；也可用 ENGDOC_CHROMIUM |
| compactIndex | false；控制原单文档 PDF 的对象附录精简，阅读式 HTML 的对象详情按需显示 |
| children | 空对象；局部别名到子配置路径，正文 project include 决定接入 |
| attachments | 空对象；PDF 附件与稳定位置映射 |

output 省略 html 时仍生成默认 HTML；只生成 PDF 应明确设置 html:false。至少启用一种输出。未知字段和类型错误会报错，不静默采用猜测值。

## 配置直接编写，数据独立维护

```js
export default {
  title: '工程手册',
  projectId: 'my-project',
  documents: 'docs/index.mdoc',
  output: { html: 'output/manual.html', pdf: 'output/manual.pdf' },
  views: [{
    id: 'project:overview', kind: 'architecture',
    include: { objects: ['project:cpu', 'project:memory'], relations: ['project:bus'] },
    layout: { direction: 'LR' }
  }]
};
```

正文引用 `{% diagram id="project:overview" /%}`。视图、表格组织和输出直接在配置文件里写，不要求导入其他 JSON 配置。工程源、知识和正文继续单独维护；不要因此把全量网表复制进配置。

data 也可直接提供标准数据对象；需要改变发现位置时，可以指定一个文件、目录或路径数组。这是可选的来源范围设置，不是要求提前枚举资源文件。

## 先扫描文档，再建立数据索引

每次运行执行以下流程，不依赖内容 hash 或历史清单：

1. 加载 JS 配置并应用缺省值。
2. 解析所有 documents 入口，递归展开 include，保留来源位置；检查正文文件、include 循环/深度、标签及图片依赖。收集全部 diagram/interface/table/waveform/reference，包含折叠和 Tabs 内的内容。
3. 执行可选的数据提供函数，或扫描数据来源。目录中按文件名顺序递归查找 JSON，跳过隐藏项和 node_modules，不允许符号链接逃出项目。
4. 为六类标准数据建立全工程 ID 索引，校验 Schema、重复 ID、关系端点、接口成员、表格投影、引用及来源路径。缺失正文引用会报告实际文档、行号和 ID。
5. 构建正文，只为正文直接引用的图形视图生成 Scene 和完整打印场景。未引用视图仍校验数据结构与静态引用，涉及实际尺寸的布局冲突在它被使用或显式导出时检查。
6. 生成配置启用的 HTML/PDF。全工程数据仍保留离线查询/搜索，未引用视图不会因没有布局而丢失原始定义。

“全部文档”指本次入口及递归 include 组成的发布集合，不把工程中的无关草稿自动加入出版物。“按需”指图形生成；普通 JSON 文件仍需读取并建立完整索引，没有宣称逐 ID 随机读取文件。

## 多文件正文与最终层级

当前 HTML 是可导航的文档阅读器，每篇正文独立显示。documents 可指定目录自动发现或有序文件数组；普通文档链接发现其他本工程页面。file include 仍在当前页内展开片段，project include 在父 section 中接入子工程树，保留各自路径与数据。

页面树与页内 section/Markdown 层级分开；输出仍是一个自包含 HTML，不等同于所有文章同时铺在页面中。每个工程的显式 section ID 仍需唯一，普通标题在页内生成锚点。子工程可独立生成，跨工程跳转只查当前产物，不能加载外部依赖。完整配置、路径规则、附件和交互见[组合工程与 PDF 附件](组合工程与PDF附件使用.md)。

## 数据格式与能力声明

docs/ir 下一个 JSON 文件可以包含一种或多种资源数组，不需要 manifest：

```json
{
  "objects": [
    { "id": "project:cpu", "kind": "node", "label": "CPU" },
    { "id": "project:memory", "kind": "node", "label": "Memory" }
  ],
  "relations": [{
    "id": "project:bus", "kind": "connection", "class": "data",
    "endpoints": ["project:cpu", "project:memory"]
  }]
}
```

支持 objects、relations、views、tables、waveforms、references。所有 ID 跨来源全局唯一，配置内定义与数据文件不能重复覆盖同一个 ID。目录中不含这些键的合法 JSON 被忽略；格式损坏的 JSON 会报错。显式指定的文件必须包含可识别数据。单个 JSON 文件上限 16 MiB，超出时分片。

IR 数据可携带 irVersion、requiredFeatures、projectId、adapterVersion。requiredFeatures 属于数据协议，不是项目配置项；未知必需能力报错，已知接口/布局结构由工具识别。普通项目无需手写版本和能力清单；省略版本使用工具当前版本，当前为 1.2。新入口对已知资源字段严格校验，不静默吞掉拼写错误。

没有 manifest 文件的加载、生成或存在性要求。实现仍使用既有 Graph.manifest 类型承载内存中的项目身份、版本等元数据，复用查询和校验，不把它暴露成用户需要维护的配置。底层 loadIR/loadConfig 仍用于历史数据夹具及示例转换验证；它们不是新 CLI 的回退路径。

原始网表、CSV、RTL 不是上述标准格式时，需要项目特有的转换。工具能发现文件和校验依赖，不能推断任意源格式的工程含义。

## 可选的项目转换函数

```js
import { convertProject } from './doc-adapter/convert.js';

export default {
  documents: 'docs/index.mdoc',
  async data({ root, documents, references }) {
    return convertProject({ root, documents, references });
  },
  views: [/* 直接编写显示定义 */]
};
```

转换函数在正文扫描成功后调用。root 为绝对项目根；documents 包含实际参与的正文/图片路径，references 包含 id、tag、file、line。返回标准数据对象、数据路径或路径数组，支持 Promise。不必先落盘生成 manifest，不要求额外配置 command/inputs，也不要求使用者单独执行 node 脚本。

加载配置和运行转换函数会执行受信任的项目代码。自动读取器只读数据；任意项目函数不是操作系统沙箱，工具不能仅凭 JS 返回值保证函数没有其他文件操作。source.file 保留追溯路径：必须位于工程内，但允许未随附原文件；这类路径不能当作原文件内容已经核验的证明。

## 命令与输出

```sh
engdoc
engdoc build --format html --output output/preview.html
engdoc validate --format json
engdoc outline --format json
engdoc query --id project:cpu --depth 1
engdoc export --view project:overview --format svg --output output/overview.svg
engdoc guide
```

所有项目命令支持 --config。无参数和 build 默认生成配置启用的全部输出；--format html/pdf 选择单一输出，--output 可覆盖该次目标。export 明确生成指定视图的完整 SVG，不受正文是否引用该视图限制。

输出不能覆盖已发现的配置、文档、数据和 source.file。所有目标先生成到临时位置，再发布；构建状态写入 .engdoc-build/build-status.json。失败不记录成功。能够确认目标与源无冲突时，失败会移除该次目标旧文件；输入尚未完整发现时保留旧产物，以免误删源文件，应以非零退出码和失败状态判断本次结果。

退出码：0 成功；1 配置/数据/构建失败；2 用法错误；3 查询 ID 不存在。validate --format json 返回文档依赖、数据文件及正文引用，便于 Agent 检查而无需读取网页。

## 安装与当前边界

npm 安装准备通过 prepare 生成普通 JavaScript、Schema、样式、浏览器资源、指南和模板。安装后直接运行 engdoc；不要求使用项目安装 TypeScript 启动器或修补 node_modules。全局 Git SSH 安装命令见 README，需要远程已有本次代码且 SSH 可访问。

本次没有引入 dev 监听、增量缓存、任意格式自动转换或全局配置修改。已增加 children、attachments 和按文档阅读，原理图 PDF 原文阅读不依赖文档导出 PDF。原网页交互、完整关系、未知值、图形质量和 PDF 要求继续生效。可运行最小与带图示例分别位于 examples/quickstart 和 examples/document-first，实际验证范围见[项目入口与自动依赖验收](项目入口与自动依赖验收.md)。
