# EngDoc V1 验收

以已批准 V1 基线为准，完成 P0–P4 通用功能主链路。保持三层架构、精确事实单一来源、只读生成、结构化查询及严格单文件交付；未进行实质架构变更。

## 关键验收事实

- Board：CSV 是唯一精确事实来源，视图和表格仅引用 ID。FLASH_SCK 保留三个端点；更改 A12 为其他 Ball 后，图形、表格与 query 一起更新，不修改正文。
- MAC：RTL 参数解析得到接口宽度；修改参数即可更新查询。架构父子框、逻辑组、接口图、状态迁移、WaveJSON 和 Spec/Case 覆盖查询共用标准 IR。
- 图形运行资源、字体和数据全部内嵌。HTML 构建不启动服务器，浏览器断网测试没有 HTTP/WebSocket 请求。
- 对象、端口、连接、表格行和显式 Spec 章节都有内部定位；查询直接返回机器资源、来源、anchor 与正反向 references。
- PDF 为单个文件：静态完整图形，全部 Tabs/details 展开，封面/目录/页码/Outline/内部链接，长表重复表头。另用 Poppler 渲染检查布局，pypdf 检查文本及缺字映射。
- SVG 文件与页面下载均通过独立 XML 解析，内嵌字体许可证正确转义；绘图虚拟 ID 不覆盖工程稳定 ID。
- 原布局中的端口偏移、父框遮挡子节点、百分号锚点、并行迁移标签重叠和 WaveDrom 全局字体污染均在开发中发现并修复，相关行为有回归检查。
- 源输入不被正常转换流程修改；Adapter 超时或失败返回错误。构建失败删除指定旧交付物，不把旧成功状态显示为本次成功。
- 每次完整转换，使用显式输入清单及 mtime/size 记录状态，没有文件内容 hash 增量机制。

## 交付与恢复

交付两个项目的单文件 HTML/PDF、可选 SVG，以及一个更新后的 EngDoc-checkpoint.tar.gz。checkpoint 内只有对应同一工作检查点的 EngDoc-latest.git.bundle、EngDoc-solution.git.bundle、EngDoc-task.md。

恢复时 clone 两个 bundle，核对 task 中两个提交号；工程中 npm ci 后可运行 validate/query/build，PDF/浏览器测试需配置 ENGDOC_CHROMIUM。方案与原始 V1 基线独立保留，未改写原方案。

## 实际限制

- 本轮在 Linux/Chromium 验证。Windows/macOS 和其他桌面浏览器尚未实测。
- 两个工程是虚构工具样例，不代表真实芯片或完整 MAC RTL；未完成真实板卡电气审核或 MAC 功能仿真验收。
- MAC Adapter 支持样例所示的 ANSI 声明和参数表达式子集，不能宣称是完整 SystemVerilog/EDA 自动理解器。
- 24 节点图验证适度规模可用性，不构成任意高密度图完美自动布局的承诺。复杂工程需拆分视图或提供位置提示。
- PDF 使用静态完整视图，不保留 HTML 筛选/拖动交互。Raw JSON 索引供追溯，精确机器读取仍应使用 query。

以上是已批准边界内的实际验证范围，不存在待用户批准的方向变更或通用功能实施阻塞。
