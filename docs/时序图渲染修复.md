# 时序图渲染修复

日期：2026-11-01。用户在图形 Demo 中发现时钟变成黑色三角形、跳变缺线、数据总线变成黑色块。此前 Demo 的检查覆盖了图形结构、交互、波形标题和输出文件，没有验证波形真正绘制后的描边与填色，漏掉了这项缺陷。

## 根因与修复

WaveDrom 使用 defs/use 复用图元。原包装将 skin 规则改成带外层 SVG ID 的祖先选择器；定义图元本身的 computed style 正常，但 use 实例树没有可靠保留这些规则，描边丢失，默认黑色填充将开放折线封成三角形。浏览器中将相同 skin 声明直接应用到图元后，方波与总线即恢复正常，确认问题属于渲染样式，不是 WaveJSON 数据。

另外，多个波形都定义 pclk、nclk、arrowhead 等相同 ID，存在跨实例引用风险。WaveDrom renderAny 还会修改传入 skin，不应让后续实例复用其已修改状态。

修复位于 packages/render-wave/index.ts：

- 每次渲染复制 WaveJSON 和 skin，不修改工程数据或共享 skin。
- 将当前默认 skin 的简单类型/类规则转成图元自身内联样式，保留原内联声明的优先级；保留描边、浅色总线、未知态纹理、字体和箭头，移除会影响正文的样式表。
- 为每个实例重命名全部 SVG ID，并同步 href/xlink:href 和 url(#...) 引用；不改变工程 Waveform ID。
- 保留规范示意/实际仿真标识和原有输出安全检查。当前支持的 WaveJSON signal 数据与时序语义未改。

这是对已接入 WaveDrom 默认 skin 的处理，不是通用 CSS 引擎。遇到不支持的 skin 选择器明确失败，后续升级 WaveDrom 时需要复验。

## 验证

新增 `npm run test:wave`，共 3 项：

1. 图元保留 skin 描边与总线颜色，不生成全局样式表。
2. 同页双实例 ID 不交叉，use 与箭头引用都在本实例内；输入数据与共享 skin 不被修改。
3. Chromium 将实际输出 SVG 栅格化，检查时钟图元内部为空白、边界有黑色描边、总线内部为浅色；同时验证双实例、正文样式与打印状态。

像素检查使用颜色与波形结构，不使用图片或文件内容 hash。它既能发现黑色三角形，也能防止以“完全不画路径”假通过。

Demo 的实际页面通过 playwright-cli 另行检查两处波形，并截取正文、查询参考与打印状态。场景保存在 examples/gallery/wave.playwright.js；离线文件继续使用 offline.playwright.js 验证。HTML 与 PDF 已重新生成，PDF 波形页进行视觉抽检；未逐页人工审阅全部 PDF。

原有 144 项兼容测试、1 项完整浏览器与 3 项 PDF 回归，以及本轮 3 项波形回归分组运行；合计 151 项工具测试。严格 TypeScript 检查通过。没有用“SVG 存在、文字可提取、构建成功”替代本轮像素和视觉证据。
