# 布局意图输入设计

状态：2026-11-01，用户批准统一展示方向后已实施第一批。本文保留设计理由与范围，当前字段和验证以[布局约束使用与验收](布局约束使用与验收.md)为准。本设计补充[二次审查](图形约束二次审查.md)的通用规则，不把已发现的缺陷转嫁给工程作者。

用户进一步提出将这一能力扩展到其他组件，全工具原则、现状和边界见[声明式展示与约束设计](声明式展示与约束设计.md)。本文件仍只讨论图形布局输入。

## 核心选择

推荐“工具提供可靠默认规则，作者声明少量布局意图”。几何避让能处理框、线和文字的空间冲突，但不能仅从连通关系得知作者希望哪条是主干、哪个是回授、阅读顺序怎样安排。

这些意图属于 View.layout。工程源继续保存端口、Net、方向和知识；视图只引用稳定 ID，不再复制 pin、位宽、端点等事实。同一份数据可生成系统总览、接口详图和查证图，各自采用不同显示意图。

输入分为三层：

| 层次 | 作者提供 | 工具负责 |
| --- | --- | --- |
| 默认绘制 | 视图范围、种类，必要的方向 | 准确挂接、真实分叉、独立关系可辨识、合理间距、标签与容器避让 |
| 布局意图 | 相对位置/对齐、主干端点、出入边、反馈通道 | 计算节点位置、锚点、干支树、线路与线上标签 |
| 精确回退 | 必要时的固定节点位置或局部路径提示 | 校验提示可行性，保留端点和完整来源，并明确报告冲突 |

少数局部提示应优先于大量绝对坐标。不要给作者几十个寻路代价参数，也不要要求每条边必须填写提示。

## 优先支持的输入

| 属性能力 | 表达的意图 | 当前状态 |
| --- | --- | --- |
| 总体方向 | 从左到右、从上到下等 | direction 已支持 |
| 接口侧边/信号顺序 | 接口在左/右，组内按指定次序 | interfaceSides、interfaceOrder、portOrder 已支持 |
| 固定位置 | 节点放在指定坐标 | positions 已支持，作为精确回退使用 |
| 相对位置与对齐 | A 在 B 左边；RX 与 FIFO 同一行；同层模块排序 | 已支持 constraints/order/align，同一项约束作用于兄弟 Node |
| 无真实端口关系的出入边 | 某条关系从模块右侧出，从另一模块左侧入 | 已支持 relationHints.endpointSides，使用显示锚点，不凭空生成工程 Port |
| 主干端点 | 一条多端点 Net 以指定的两端为显示主干，其他端点作为分支接入 | 已支持 relationHints.backbone，全部原端点保留，不代表 PCB 实际拓扑 |
| 通路角色与通道偏好 | 主通路优先布线，反馈优先从下方绕回 | 已支持 priority/channel，仅是本图阅读意图，不改 class/方向；channel 目前只适用于两端点关系 |

第一批围绕相对位置/对齐、关系出入边、主干端点和反馈通道落实，已有属性继续复用。IR 需声明 layout-intent 必需能力；项目级默认与引用处覆盖尚未实现。

## 两张图如何使用

MAC 图只需描述：Control 在 Data plane 左侧；TX/RX 在容器内上下排列；RX 与 FIFO 对齐；received frame 是希望优先阅读的通路；occupancy event 使用独立反馈通道。工具仍必须自行分配不同出线点、合理线距与边界穿越位置。

FPGA–Flash 图只需补充：时钟显示主干选 FPGA 与 Flash，测试连接器保留为该 Net 的第三个端点。下面是已支持字段的局部例子，完整 manifest/作用域要求见使用契约：

```json
{
  "layout": {
    "direction": "LR",
    "relationHints": {
      "board:net.FLASH_SCK": {
        "backbone": ["board:U1.QSPI_CLK", "board:U5.CLK"]
      }
    }
  }
}
```

这不需要再列一遍第三端点，也不需要填写分叉点和每个折点坐标；它们由原始关系与实际布局求得。圆点必须依据实际渲染树绘制，不能继续画在错误的虚拟 hub 上。

## 约束与冲突处理

- 事实与基本正确性必须满足：真实端点、方向和多端点身份不变，分叉标记对应真实连接；没有提示时同样要做到。这些不是可关闭的美观选项。
- 相对位置、侧边和主干等提示需要校验稳定 ID 与作用域。backbone 必须是同一原关系中的两个不同端点，不能生成额外连接。
- 默认把“优先直行”“优先下方反馈”等当作偏好；放不下时可选择其他合法路径，并给出可理解的说明。
- 作者明确锁定的位置、边或其他必须满足的约束，遇到冲突应报出涉及的对象和提示，不能悄悄违背。第一批以字段区分：order/align 和 endpointSides 是必须满足的约束，priority/channel 是偏好，不为所有提示强制增加 required/preferred 包装。
- 同一接口展开/折叠后，提示仍引用原 Node/Interface/Port/Connection ID，通过显示投影映射；不让作者引用临时槽位或聚合线的内部 ID。
- 主干、顺序和反馈通道只影响阅读与布局，不推断总线协议、实际电流路径或 PCB 信号传播路径。

高级路径提示仍作为后续回退方向，当前公开接口尚无任意折点字段。输入扩展需要 Schema/引用校验、冲突诊断、缺省行为以及网页/SVG/PDF 同源验证。本批也修复通用路由的共线、框边标题和分叉标记，具体范围见使用与验收，不能靠增加输入属性掩盖默认渲染缺陷。
