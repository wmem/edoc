# 接口分组与连线展开设计

状态：用户已于 2026-11-01 批准实施第一版，批准原话为“按照你的方案实施一个我看效果”。正文保留设计提出时的措辞；当前已实现接口与验证边界见[接口分组实现与验收](接口分组实现与验收.md)，实际 API 见 [V1 开发与使用](V1-开发与使用.md)。本文件不再作为“功能尚未实现”的说明，也不将未来通道层级或性能目标当作已完成能力。

用户目标：同一模块可以拥有多组 AXI 等总线，整体阅读时每组显示为一个接口端口及对应聚合连线；展开某一接口后，看到实际定义的信号及逐信号连接。端口展开与连线展开必须联动，其他接口可以继续保持折叠。

## 1. 当前实现与缺口

当前已有 Node、Port、Connection、Group，以及 Port.groupId、view.display.collapsedGroups：

- [类型定义](../packages/core/types.ts)中的 Group 是通用逻辑集合，可跨模块、可包含节点或端口，没有唯一的接口所属模块。
- [客户端总览](../packages/doc-theme/client.ts)在端口组折叠时隐藏有关关系，收集所有相关模块，从第一个模块向其余模块绘制粗线。端口仍在原节点里，没有压缩端口列表，也没有按接口端点对区分聚合线。
- [Scene](../packages/render-graph/index.ts)按全部可见信号计算节点尺寸，没有 InterfacePort、Bundle 或成员映射。目前不会因展开/合并重新布局。
- [接口表格](../packages/doc-theme/render.ts)的 overview/detailed 可以展示组汇总或逐端口，但不是图内接口与连线联动展开。
- MAC 样例的分组由项目语义文件声明，其 TX/RX/APB 接口图没有真实跨模块信号 Connection，不能据此证明已有双端总线展开能力。
- 当前分组总览主要在客户端临时绘制，完整 SVG/PDF 保留原信号视图，不能复用它作为新的接口投影和静态导出实现。

原始方案要求接口固定边、顺序、组别和逐信号完整性，总线折叠不得合并真实独立关系，见[原方案 §3.2–3.4、§6.2](design/EngDoc-V1-完整设计方案.md)。下面的聚合只改变显示，保留这些要求。

## 2. 推荐的人机行为

一个模块可以同时有 `S_AXI_CTRL`、`M_AXI_DMA` 等不同接口。每个接口有自己的展开状态，不把模块内所有 AXI 接口合成一个端口。

折叠时，模块边缘呈现接口名称、可选角色和展开标记，例如 `▶ S_AXI_CTRL · slave`；连接的两端都折叠时，显示一条有接口标识和关系数量的聚合线。它采用有别于真实 Net 的接口符号/线型，不能用电气汇合点暗示成员信号被短接。

| 两端状态 | 端口与连线显示 |
| --- | --- |
| 都折叠 | 两个接口端口；相同完整接口端点集合的多条关系可以投影为一条聚合线 |
| 只展开一端 | 本端恢复成员信号，对端保留接口端口；逐信号线进入对端接口区域的独立槽位，保留每条关系的身份 |
| 两端都展开 | 恢复真实信号端口、独立关系、方向、标签与多端点分支 |
| 同一模块的其他接口未操作 | 保留各自展开状态，不能被一起展开或合并 |

交互分工：点击接口的展开标记只展开这一端；点击接口名称查看接口属性；点击聚合线查看所含原关系，并提供“展开两端接口”。工具栏提供“接口总览”“全部展开”。两端模式可独立操作，第一版同时支持这三种组合，不先做只能整图折叠的近似功能。

展开的对象是源数据中实际定义的成员信号，不按协议模板补齐信号。端口显示可沿用现有“端口属性”开关，逐信号/聚合标题沿用“连线标题”开关，二者与接口折叠是不同维度。

端口未参与当前视图的关系时，标为“本视图未显示连接”；不能直接断言它在实际电路/RTL 中未使用。接口面板分别显示完整成员数、当前视图成员数和可见关系数。向量位宽不计为信号条数，混合宽度也不能相加为一个所谓“接口位宽”。

## 3. 事实模型：模块拥有接口，接口引用信号

推荐在 Node 上增加可选 interfaces 数组，在索引中注册独立的 interface 实体。接口的 owner 由嵌套节点确定，不重复存 ownerId，也不同时要求每个 Port 再写 interfaceId。

下例为提议字段，只有局部成员，用于解释归属，不是完整 AXI 协议定义：

```json
{
  "id": "ip:engine",
  "kind": "node",
  "label": "处理模块",
  "ports": [
    {"id": "ip:engine.s_awvalid", "label": "s_awvalid", "direction": "in", "width": 1},
    {"id": "ip:engine.s_awready", "label": "s_awready", "direction": "out", "width": 1},
    {"id": "ip:engine.m_awvalid", "label": "m_awvalid", "direction": "out", "width": 1},
    {"id": "ip:engine.m_awready", "label": "m_awready", "direction": "in", "width": 1}
  ],
  "interfaces": [
    {
      "id": "ip:engine.s_axi_ctrl",
      "label": "S_AXI_CTRL",
      "protocol": "AXI4-Lite",
      "role": "slave",
      "members": ["ip:engine.s_awvalid", "ip:engine.s_awready"]
    },
    {
      "id": "ip:engine.m_axi_dma",
      "label": "M_AXI_DMA",
      "protocol": "AXI4",
      "role": "master",
      "members": ["ip:engine.m_awvalid", "ip:engine.m_awready"]
    }
  ]
}
```

约束：

1. interface.id 与工程中其他稳定 ID 一样全局唯一；重命名 label 不改变引用。
2. members 非空，只能引用当前 Node 的真实 Port；跨模块归属、重复成员、缺失引用明确报错。同一 Port 第一版最多归属于一个接口，避免折叠时出现两个归属；通用逻辑 Group 仍可重叠。共享时钟等保留为独立 Port，通过已有 clockDomainId 等显式关系引用，不为每组接口复制真实端口。确实需要同一端口同时归属多个接口的工程，需后续设计显示别名，第一版不能静默接收这种歧义。
3. protocol、role 是项目提供的开放描述，工具不内建 AXI 信号清单、角色兼容判据或前缀推断。未知信息留空或保留项目的未知描述，不由 role 推断所有信号方向。
4. 方向、位宽、时钟域、Ball/Pin 和 source 仍只在原 Port 中维护。成员关系在接口 members 中定义一次，反向查询由工具建立索引。
5. 接口可提供 source/attributes 追溯项目知识或接口声明；缺失的接口语义由项目 Adapter/知识补充，不由通用渲染器猜测。
6. 原 Group 和 Port.groupId 保留原含义，不自动转换成接口。现有项目不声明 interfaces 时，行为保持。
7. Connection.endpoints 继续只引用真实 Node/Port，不能将接口 ID 写进去替代逐信号连接。仅声明接口、没有原始 Connection 时，不虚构聚合连线。

view.include.objects 可引用接口 ID，只选入该接口成员，不自动引入所属模块的其他接口。现有 Markdoc interface 标签增加接受 interface 实体作为目标，overview/detailed 分别展示接口汇总和真实成员；原有 node/group/view 目标继续支持。

选择独立接口对象的理由：Group 同时承担逻辑集合、跨模块集合与节点折叠；接口则必须有唯一所属模块、可检索身份和真实成员。强行给任意 Group 解释 master/slave 归属，容易改变已有工程含义。

未来可以增加通用的接口内子组，如项目声明的 AW/W/B/AR/R 等通道；第一版先完成“接口 ↔ 信号”两级，不把 AXI 通道写进工具核心。

## 4. 显示状态属于视图

拟增加如下可选视图字段：

```json
{
  "display": {
    "interfaceMode": "collapsed",
    "interfaceOverrides": {
      "ip:engine.m_axi_dma": "expanded"
    }
  },
  "layout": {
    "interfaceOrder": ["ip:engine.s_axi_ctrl", "ip:engine.m_axi_dma"],
    "interfaceSides": {
      "ip:engine.s_axi_ctrl": "left",
      "ip:engine.m_axi_dma": "right"
    }
  }
}
```

mode 只允许 collapsed/expanded。省略接口显示配置时默认 expanded，保持现有逐信号输出；推荐理解性总览显式选择 collapsed。用户在网页中的展开状态逐张图独立，不写回 IR，刷新恢复视图初始配置。

同一接口展开后，其信号仍按接口的整体固定边放置，组内沿用已有 portOrder；没有提示时按项目声明顺序。没有固定边提示时按邻接布局选边，不从 slave/master 推断 in/out。未归属于接口的原端口沿用既有规则。

仅包含一部分成员的视图可以折叠这部分，但必须展示“本视图 k/N 成员”并能查看完整接口；不能看起来像整个接口只包含 k 个信号。视图内的包含范围与分类过滤分别处理，不因接口存在而自动添加不在 view.include.relations 中的关系。

## 5. 连线聚合是有来源的显示投影

建议增加共享的 projectScene(facts, view, state) 层，位于工程事实与布局之间：

```text
原 Node / Interface / Port / Connection
                 ↓ 视图范围与分类
显示端点投影：真实信号端口 → 当前可见信号或接口端口
                 ↓ 按完整可见端点集合分组
DisplayConnection / DisplayBundle + 原始 ID 映射
                 ↓ 共用布局、路由和线上标签
X6 / SVG / PDF
```

显示端点需要明确区分 signal-port 与 interface-port，不能将接口端口冒充真实电气端口。每个投影保留 originalPortIds；每条聚合关系保留 sourceRelationIds、每个关系的完整原端点及其映射、类别集合和方向摘要。显示用 Cell ID 使用类型和稳定原 ID 组合，避免碰撞，不引入内容 hash。

聚合规则：

- 原关系先完整映射端点。只有完整投影端点集合一致、且接口端点参与的多条关系，才可以归入同一 Bundle；没有折叠接口参与的关系仍逐条绘制。
- 同样是 A 模块连 B 模块，A.S_AXI_CTRL、A.M_AXI_DMA 等不同接口对必须分别聚合，不能只用模块 ID 当分组键。
- 两端接口都折叠时，相同端点集合的多条关系可以共用一个 Bundle；只展开一端后，各信号端点不同，自动变成独立连接，不强行继续画一条失去映射的粗线。
- 同一接口的成员连向不同模块/接口时，分别显示对应连接。含第三端点的 Net 按完整端点集合绘制分支，不把 A–B 与 A–B–测试端口混为同一条接口线。
- 多个真实端点投影为同一个接口端口时，只可合并视觉挂接，保留每个原端点映射。若一条关系的全部端点都落在同一折叠接口内部，计入接口内部关系提示与面板，不伪造对外自环；展开后恢复。
- 混合类别、相反方向的信号可以属于同一接口 Bundle；用专用聚合样式和类别/方向摘要表达，不取第一条信号的颜色、方向和标签代表全部成员。接口角色也不替代逐信号方向。
- 标题显示接口名和关系数，点击能逐条查来源；分类过滤先作用于原关系，再重建 Bundle。可以显示“可见 8/12 条”，全部被过滤时不画残留聚合线。
- 数量明确指端口或原关系数量，不把向量位宽当信号数，也不把原有多个独立关系宣称为一条新 Net。

展开/折叠往返后，真实 Port 和 Connection 的 ID、成员关系、端点、方向、来源必须完全一致。这是语义验收核心。

## 6. 布局与离线实现

不能只隐藏文字：折叠后模块高度应按“接口行 + 独立信号行”收紧；展开后重新计算端口位置、节点大小、路径、标签和画布范围。

推荐复用已依赖的 ELK，将无文件系统依赖的投影、布局与路由整理为构建端/浏览器共用模块，通过 LayoutEngine 注入环境实现。浏览器单文件内嵌所需引擎，不动态下载代码，不启动外部 Worker，不访问工程文件。新增交付大小、首次加载时间和展开延迟必须实测，不能仅因“已有依赖”就承诺无体积/性能影响。

不预生成全部接口状态组合：n 个接口的状态数为 2^n，不适合每份 HTML 内嵌全部布局。按当前状态计算当前视图；显示状态与成功状态显式管理，不用文件内容 hash。

自动布局需要保持缩放和当前操作模块的屏幕锚点，避免每次展开都跳回整图适配；第一版不要求复杂过渡动画。重复操作时只提交最新请求且布局成功的状态，失败恢复上一个可读场景，并清楚报错。

固定位置仍优先遵守原位置。若展开后的节点与固定邻居重叠，明确提示该视图的空间不足，保留原场景并允许查看信号详情；不能悄悄移动固定节点或只在面板展示信号却宣称图内已展开。需要与自动布局分别验收。

## 7. 选择、查询、标签与导出

- 接口本身可搜索、引用和查询；查询接口时列出成员端口，并从成员邻接索引汇总原始直接关系。查询不受网页折叠影响，继续遵守现有展开限额和截断标识。
- 点选 Bundle 时显示“显示聚合”详情与 sourceRelationIds，并能跳到每条真实关系、端口和来源。它不注册为新的工程 Connection，也不冒用原 Net ID。
- 选中真实信号但其接口折叠时，定位到该接口并提示可展开；“定位信号”操作可以显式展开必要接口，不展开其他接口。
- “端口属性”继续控制信号附注；“连线标题”同时控制真实线与 Bundle 的名称。隐藏标题不隐藏接口展开控件、端口或路径。
- 保留现有完整 SVG 导出的语义：原 SVG 入口和 CLI 默认生成全部展开的信号视图；增加显式“当前接口视图 SVG”导出，用当前状态投影并保留成员/原关系 metadata。该选项必须清楚标为汇总或混合视图，不能冒充逐信号图。
- PDF 和浏览器打印默认输出全部展开的信号视图，与当前“展开折叠、保留完整内容”约定一致。若正文需要接口总览，可增加明确的总览图并链接完整信号详情；不把网页折叠状态直接用于省略 PDF 内容。
- HTML、当前视图 SVG、展开 SVG 和 PDF 共用同一投影/布局底座，不再由客户端另画一套只能粗略连模块的线。

## 8. 兼容与需要批准的新增约定

不修改原始方案快照。旧 Group、groupId、Node.parentId、逐信号 Connection、多端点身份、源数据/视图分离继续有效。

以下是本提案需要批准的扩展，而非已生效规则：

| 当前约定/实现 | 拟采用的约定 | 理由及影响 |
| --- | --- | --- |
| Group 是通用逻辑集合，Node 尚无 interfaces | 新增 Node.interfaces 与可查询 interface 实体，旧 Group 不自动迁移 | 明确模块拥有的接口；Adapter 可选增加成员语义，查询/引用/Schema 需要扩展 |
| 当前 interface 图按单个信号方向分边 | 已声明接口的成员在同一接口固定边整体展开，真实方向保持 | 保持同一接口在模块边界的归属；旧端口保持旧规则，不把 slave 误标为全部输入 |
| 总览使用客户端临时粗线，静态图使用完整原视图 | 新接口模式使用共享投影与布局；默认完整导出保留，新增显式当前状态 SVG | 三种展开状态与跨格式一致；前端需要内嵌布局能力，大小/延迟须验证 |
| IR 1.0 现有可选字段和必需能力白名单 | 新接口字段作为同 major 的 minor 扩展，增加 interface-groups 必需能力协商 | 旧工程继续可用；使用接口引用或新投影的工程明确要求该能力，旧工具不能静默忽略 |

建议新示例使用 IR 1.1 并声明 requiredFeatures 中包含 interface-groups；确切版本名在实现时统一。所有旧 IR 1.0 样例继续回归。本文 JSON 尚不应写入当前生产 IR。

## 9. 实施范围与验收

建议第一轮交付一个完整的“接口 ↔ 信号”功能，包含双端、单端和混合状态，不分散为先加按钮、再补语义：

1. 模型/校验/查询：Node.interfaces、成员唯一归属、反向索引、引用与必需能力；原 Port/Connection 不变。
2. 共用投影：接口端点、聚合关系、来源映射、筛选及多端点规则；先验证折叠往返不改变工程事实。
3. 共用布局与交互：节点尺寸收紧、单端展开、双端展开、接口内固定边、选择/高亮、失败恢复与离线运行。
4. 导出与 Demo：当前/完整 SVG 和完整 PDF；建立“控制模块 → 双接口处理模块 → 存储模块”的虚构样例，包含两个独立接口和真实逐信号 Connection。现有 MAC 无真实接口接线，不能只改其按钮冒充验证完成。
5. 推荐指南：实现验收后再加入接口组织建议、Adapter 示例与导出说明，不让未来 Agent 根据尚未实现的字段生成工程。

最低验收场景：

- 一个模块至少两组接口，操作其中一组不改变另一组状态与成员。
- 同一模块对之间有两组接口，各自连接不混在一条粗线上。
- 两端折叠、仅本端展开、仅对端展开、两端展开，以及反复往返。
- 同接口混合 in/out、参数宽度未知、向量信号、部分成员视图、当前视图未连线成员。
- 接口连接多个目标；一个信号有第三端点；只有部分信号带额外端点；接口内部连接。
- 类别/方向混合、过滤后计数与路径一致、标题和属性两个开关组合。
- 默认 SVG/CLI/PDF 保持完整信号；显式当前 SVG 与网页状态一致，metadata 可追溯全部组成关系。
- playwright-cli/Chromium 检查真实端口挂接、路径/标签、节点收紧、选择、缩放锚点、窄屏、file:// 断网零外部请求与字体；实际查看代表性 SVG/PDF。
- 测量 HTML 大小与展开延迟，报告测试规模和浏览器环境，不能承诺未实测的性能。

本提案已获用户批准，第一版使用虚构的多接口样例，不依赖提供真实 AXI 工程。实现、测试与实际可用边界以[实现与验收](接口分组实现与验收.md)为准。
