# V1 开发与使用

接入与组织正文前先读[推荐指南](推荐指南.md)。推荐的阅读路线、理解正文与查询参考的区分，以及正文模板入口由该指南统一维护；这些建议不改变工程规范和数据契约。

EngDoc 以独立方案仓库的《EngDoc-V1-完整设计方案.md》为设计基线。通用工具、项目源数据、项目 Adapter 三层分离；本文描述当前实现和接入契约。

## 从一个项目开始

1. 保留原有工程事实。精确字段来自 RTL、引脚约束、网表、配置或项目唯一权威数据。
2. 用项目转换脚本生成 EngDoc IR。缺失的语义单独补充，不能复制已有引脚或接口位宽。
3. 用 `.md` 写普通正文，用 `.mdoc` 使用受控布局与数据引用标签。
4. 运行 validate/query 做精确检查，再按需要 build HTML 或 PDF。

Adapter 的正常数据不能硬编码在脚本中。示例 Board 将器件、引脚和 Net 分开定义；示例 MAC 从 RTL 读取端口及参数，project/semantics.json 只补充架构与覆盖映射。

两个项目是虚构的工具验收样例。它们有实际存在、可转换的源文件，但不代表真实芯片引脚或 MAC 功能实现。

## 配置与转换契约

```json
{
  "projectId": "my-project",
  "title": "工程文档",
  "irDirectory": ".engdoc-build/ir",
  "adapter": {
    "command": ["python3", "doc-adapter/convert.py"],
    "version": "1.0",
    "timeoutMs": 30000,
    "inputs": ["board/pins.csv", "docs/views.json"]
  }
}
```

配置文件所在目录为允许的项目根。adapter 可省略，此时直接加载已有 IR。命令按数组执行，不经过 shell；只对受信任项目运行。

转换程序从 `ENGDOC_IR_OUTPUT` 读取本次临时输出目录，在其中写 manifest 与资源。manifest.adapterVersion 必须与配置一致。inputs 是需要存在的文件清单，作为显式依赖；不允许 IR 输出目录包含这些输入。当前不使用增量缓存，每次重新运行转换。脚本须只写自己的输出目录，禁止修改原工程和通用工具。

工具检查声明输入的 mtime/size 未被改变；这不是任意程序的操作系统沙箱。转换失败、超时、IR 校验失败均返回非零退出码，并记录失败状态，不回退旧查询。构建失败会移除本次指定的旧 HTML/PDF 交付物，避免把旧文件当成新成功结果。

路径必须在项目范围内，资源和入口文档必须存在；禁止绝对路径、URL 路径和符号链接逃逸。source.file 可表示未随附原始文件，但不能越界，也不能声称其内容已通过一致性验证。

## IR 资源

manifest 的 resources 是 type/path 列表，允许同类多分片，不能重复同一实际文件。资源路径相对 manifest；entryDocuments、source.file 相对项目根。所有 JSON 使用 UTF-8，单分片最多 16 MiB。

| 资源类型 | 文件外层数组 | 主要内容 |
| --- | --- | --- |
| objects | objects | node 和逻辑 group，node 内嵌有独立稳定 ID 的 ports |
| relations | relations | connection，至少两个不同端点；一条多端点 Net 保留一个 ID |
| views | views | architecture/interface/wiring/state，仅引用工程 ID 与布局/显示策略 |
| tables | tables | 列字段/显示名/类型/单位，有稳定 ID 的行；可从对象投影 |
| waveforms | waveforms | format=wavejson，semantic=specification/simulation，数据及来源 |
| references | references | fromId、targetId、class，表达描述、覆盖或包含等关系 |

每个 node、port、group、connection、view、table、row、waveform、reference 及显式文档 section 的 ID 跨分片全局唯一。ID 不由 label、行号或内容 hash 派生。port 所属 node 从结构确定；node.parentId 与 group.members 分别表示层级和逻辑集合。

端口方向支持 in/out/inout/passive/unknown。width 是已解析正整数；未解析时保留 widthExpr 和 parameterContext。clockDomainId 显式引用已声明对象；工具不推断时钟或协议含义。

connection.class 是开放字符串。方向可通过 sources/targets 显式声明，不从类别或颜色推断。视图折叠与分类过滤不修改原始 endpoints。多端点图使用有共同关系身份的分支和汇合点；图中的多条绘制路径不是多条 Net。

表格行二选一：`{id, objectId}` 从已有对象投影，或 `{id, values}` 保存权威表格行。字段如 attributes.ball 使用点路径。不能在 objectId 行再次复制精确值。可用字段缺失时显示 unknown，不猜测数值；已存在的值须与列 type 一致。

参考所有资源的正式 JSON Schema：packages/schema。通用 schema 由 Ajv Draft 2020-12 校验，之后做 ID/引用/类型/循环/方向/表格/WaveJSON 检查。错误包含 code、file、JSON Pointer 或文档行，以及可识别的对象 ID。

## 版本兼容

基础样例沿用 IR 1.0，当前工具支持 IR 1.2，接口分组在 IR 1.1 增加，布局意图在 IR 1.2 增加。同 major 的后续 minor 可以增加可选字段；读取时保留这些字段，已知结构仍校验。未知 kind、资源类型、major 或必需能力明确失败。manifest.requiredFeatures 声明必须理解的能力；当前支持 graph/documents/tables/wavejson/references/interface-groups/layout-intent。

IR 1.0 对拼错字段严格报错。后续 minor 的未知可选字段不执行为代码，也不改变已知关系语义。文档标签版本当前为 1.0，未知标签/属性/引用不会静默忽略。

## Markdoc 正文与布局

```text
{% section id="SPEC-TX-001" title="发送接口" %}

普通 Markdown 段落、标题、列表、代码和表格。

{% columns ratio="2:1" %}
{% panel title="结构" %}
{% diagram id="project:overview" /%}
{% /panel %}
{% panel title="约束" %}
{% reference id="project:tx" /%}
{% /panel %}
{% /columns %}

{% interface id="project:tx" mode="detailed" /%}
{% table id="project:port-table" /%}
{% waveform id="project:handshake" /%}
{% /section %}
```

| 标签 | 当前属性与行为 |
| --- | --- |
| section | 稳定 id，title 可选，collapsed=true 可折叠 |
| columns | ratio 预设为 1:1 / 2:1 / 1:2 / 1:1:1；窄屏堆叠 |
| panel | 可选 title，正常嵌套 Markdown |
| tabs / tab | tab.name 必需；HTML 切换，PDF 顺序输出全部 |
| diagram | id 指向 view |
| interface | id 指向 node/group/view；detailed 逐真实信号展示，overview 保留接口总览 |
| table | id 指向结构化表格 |
| waveform | id 指向 WaveJSON，显示规范示意或实际仿真标识 |
| reference | id 可指向任意已声明工程对象、行或显式 section |

显式 section 会加入全局查询索引；没有稳定 ID 的普通标题仅用于当前文档目录。章节来源文件可继续分开，发布时按 entryDocuments 顺序合并为一个文档，不生成多页路由。

### 章节树与正文引用

正文可用 `{% include file="docs/module.mdoc" /%}` 引用项目根范围内的 `.md` / `.mdoc`。工具在解析时组合结构，保留被引用文件的章节来源和行号；循环、超过 32 层的 include 嵌套、路径/符号链接逃逸、未知属性与重复稳定 ID 均明确失败。入口文件应写完整的 section，不能跨文件拼接未闭合标签。

section 嵌套表达显式章节层级；其内部最浅的 Markdown 标题从下一层开始，其他标题保留相对级别。正文标题位于封面标题之下，HTML 的 h2–h6 用于可用层级，超过部分以 aria-level 和 outline 保留实际深度。布局 panel 的 title 仅作为布局标题，不进入正文目录或 PDF 书签。该规则修正原实现将 section 和目录扁平化的显示问题，不改变正文条款。

HTML 侧栏使用可折叠目录树，打印目录使用同一结构展开显示，PDF 由对应正文标题生成书签。`engdoc outline --config engdoc.config.json --format json` 返回章节的 id、label、level、depth、parentId、source 与 children，Agent 无需读取 HTML 即可检查结构。`engdoc guide` 提供写作与组织建议。

正文不执行原生 JS/CSS/HTML。普通外链仅允许 http/https/mailto，运行资源不能外链；本地 PNG/JPEG/WebP 图片在项目范围内读取并内联。不支持把 arbitrary HTML/SVG 附件作为正文执行。

## 图形与交互

本节说明当前接口，不代表图形质量已经完成验收。原始要求见[需求与设计基线](需求与设计基线.md)，真实工程已发现的路由与标签问题见[图形渲染审查](图形渲染审查.md)。

普通自动布局保留 ELK 的连线路径，为线上标题预留空间，再将标题定位到所属真实线段；真实 port 固定位置，无端口框分配独立出线位置。固定位置或层级图使用避障回退，预留端口出线走廊和标签空间；找不到可读通道/标签位置时明确失败。当前 layout.positions 是节点位置提示，没有任意折点路径提示字段。路径修复历史见[图形渲染修复验收](图形渲染修复验收.md)，当前文字控制见[图形文字显示](图形文字显示.md)。

四类预设共用场景模型，ELK 提供自动层次布局；layout.positions 可提供显式位置回退，routing 支持 orthogonal/polyline，direction 支持 LR/RL/TB/BT。接口支持端口固定边及排序，wiring 显示 Ball/Pin/功能，state 使用关系 label 表示条件，不自动解析 HDL 状态机。

X6 提供只读图形交互：缩放、平移、适配、对象/端口/关系选中、邻接高亮、分类过滤、分组总览/展开和属性跳转。port 组总览以总线视图表示，node 组可折叠为集合节点；展开不改变任何工程身份。

完整视图的 X6 路径与标签直接使用 Scene 几何，不重新决定端点。关系名称显示在线上，类别通过图例/筛选及属性保留。大图查看展开当前画布，Esc 退出；清晰阅读恢复 1:1 比例，再拖动浏览。适配画布用于完整总览，不能保证任意宽图在该比例下的文字都清楚。

display.classes 指定 HTML 初始分类选中状态；PDF 和 SVG 完整视图导出保留该 view.include 的全部关系。静态输出若要只展示部分关系，应直接使用独立 view.include。未显示实体仍可 query。

SVG 同源生成，包含物理标签、全部连接端点和来源 metadata，并内嵌中文字体。复杂图需拆视图或调整提示；不承诺任意密度完全自动排版。

### 图形文字显示

端口始终保留名称与连接位置，属性附注默认隐藏；连线标题默认显示在所属线段上，以背景留白避免线穿文字。工具栏“端口属性”“连线标题”两个开关逐图独立，切换不移动端口、不重新布局、不删除工程属性或关系。端口的 `function` 属性与名称完全相同时，只省略附注中的重复功能名；原始字段与 query 保留。

视图可通过 `display` 指定初始状态，例如详细接口或精确接线图可设置：

```json
{
  "display": {
    "portAttributes": ["ball", "pin", "function"],
    "showPortAttributes": true,
    "showRelationLabels": true
  }
}
```

`portAttributes` 选择附注包含的扩展字段；`showPortAttributes` 控制整行附注，包含方向、位宽和时钟域。后两项省略时分别为 `false`、`true`。工具构建的 HTML、CLI SVG 与 PDF 使用相同初始设置；网页中切换后，该图 SVG 下载和浏览器打印同步文字状态，预先生成的 PDF 不随网页操作变化。开关只控制文字，类别筛选和分组仍保留原有完整视图导出约定；刷新网页恢复视图初始设置。

### 接口端口与连线展开

IR 1.1 增加 Node.interfaces，使用时在 manifest.requiredFeatures 声明 `interface-groups`；旧 IR 1.0 和 Group/groupId 行为保留。接口嵌套在唯一所属 Node 下，由 id、label、非空 members 组成，protocol、role、source、attributes 可选。members 引用本节点真实 Port；同一 Port 第一版只能属于一个接口，不能以接口 ID 替代 Connection.endpoints。角色与协议是开放的项目描述，不推断信号方向或补齐协议成员。

```json
{
  "interfaces": [{
    "id": "ip:s_axi", "label": "S_AXI", "protocol": "AXI4-Lite", "role": "slave",
    "members": ["ip:awvalid", "ip:awready"]
  }]
}
```

上例是 Node 的局部字段；真实 Port 仍由源数据提取，接口只引用其稳定 ID。view.include.objects 和 Markdoc interface 标签可以直接引用接口。查询接口可取得完整成员和原始直接关系，展开限额保持原约定。

接口视图、显式配置 interfaceMode/interfaceOverrides 的视图，或直接包含接口 ID 的视图启用接口投影；普通架构图不会因新增接口元数据自动更换布局。display.interfaceMode 为 collapsed/expanded，省略时逐信号展开；display.interfaceOverrides 用接口 ID 指定个别状态。layout.interfaceOrder、interfaceSides 分别控制接口顺序与 left/right 固定边，组内沿用 portOrder。真实方向与显示边分开。

网页可独立展开/合并一端，或从聚合线选择“展开两端接口”；节点大小、端口与连线共同重新布局，并保留缩放和操作节点的屏幕锚点。两端折叠时按完整投影端点集合聚合，单端展开时使用独立挂接槽位，多端点不丢失，聚合可查组成关系。分类作用于原关系后再聚合；端口属性与标题两个开关继续有效。

原 SVG 按钮和 CLI export 默认导出全部展开视图，PDF/浏览器打印也保留全部展开内容；新增“当前视图 SVG”显式导出网页当前状态和来源 metadata。构建同时检查完整逐信号输出，固定位置若容纳不下完整展开，会明确失败，需要调整位置或拆视图。运行中布局失败保留上一个成功场景。

第一版不提供通道层级、端口跨接口别名或新接口视图内的旧 Group 粗线总览；Group 仍可作为选集，原有无接口声明的视图与总览不变。详见[实现与验收](接口分组实现与验收.md)。

### 时序图

时序图使用 WaveJSON signal 数据，保留规范示意/实际仿真及来源。同页多次引用时，SVG 图元和本地引用按实例隔离，skin 样式保留在图元自身，避免 use 复用丢失描边或污染正文。实现和实际像素回归见[时序图渲染修复](时序图渲染修复.md)。

### 按需声明布局意图

使用新属性时在 manifest.requiredFeatures 声明 `layout-intent`，建议写入 IR 1.2。View.layout.constraints 支持同父容器 Node 的 order/align，axis 为 x/y，nodes 为稳定 ID 列表；order.gap 是最小间距，默认 80、最小 16，工具会为标题等增加空间。顺序、中心对齐与已有固定位置冲突时明确失败。

View.layout.relationHints 按原 Connection ID 设置：backbone 引用同一原关系的两个不同端点，endpointSides 指定 Node 端点的 left/right/top/bottom，channel 是两端点关系的外侧通道偏好，priority 为 main/normal。它们只表达显示意图，不改变方向、类别或端点；endpointSides 不覆盖真实 Port。通道偏好无法满足时说明原因，没有合法路径仍失败。

接口投影沿用原稳定 ID，有专属提示的原关系保持独立显示线。网页、SVG 和 PDF 共享布局结果。拼写、引用、作用域与静态循环在 validate 校验，涉及实际尺寸的冲突在 build/export 时校验。当前尚无项目默认/引用覆盖链或任意折点字段。完整例子、输出规则和验收入口见[布局约束使用与验收](布局约束使用与验收.md)。

## 查询接口

```bash
engdoc query --config engdoc.config.json --id project:object --depth 1 --format json
```

也可用 node packages/cli/engdoc.ts 或 npm run engdoc -- 调用。

返回 irVersion、projectId、target、directRelations、references、expansion。target 包含原始 entity、资源位置、来源、稳定文内 anchor；端口另有 ownerId。references 同时返回正向和反向关联，例如 Case → Spec 的 covers。

默认 depth=0，直接连接保持完整，不递归加载整个工程。显式 depth 范围 0–10，max-items 默认 1000、范围 1–10000；截断只限制展开实体，truncated 明确提示，不截短 Net 端点。查询无需读取生成 HTML 或 SVG。

公共 TypeScript API 由 packages/core/index.ts 导出：loadConfig、loadIR、validateSchema、query、summary、outline、EngDocError 及资源类型。loadConfig 会按受信任配置运行 Adapter；loadIR 只读取指定 IR。

退出码：0 成功；1 数据/文件/构建失败；2 命令用法错误；3 查询 ID 不存在。成功数据写 stdout，错误写 stderr；--format json 返回结构化诊断。

## HTML / PDF 与恢复

HTML 的 CSS/JS/字体/SVG/图片/数据全部内嵌，使用 IIFE，无运行时分包、Worker、外部网络或本地服务器。页面 CSP 禁止 connect-src 和外部代码。只有显式点击普通外链会导航到外部页面。

PDF 由同一文档的打印布局生成；展开所有 Tabs/details，使用静态 SVG 完整范围，A4 横向页面、封面、目录、Outline、内部链接与页码。长表重复表头并跨页；不保留 HTML 拖动/筛选交互。

工程 bundle、方案 bundle 和最新 task 一起构成 checkpoint。恢复后先读 task、核对 HEAD、npm ci，并配置 ENGDOC_CHROMIUM；示例 Adapter 可重建 IR。依赖与环境说明见 env-notes.md。
